## 문제와 제약

카드 인식 모델이 프레임에서 정답을 출력하는 것만으로 방송 도구가 완성되지는 않습니다. 인식 결과를 안정적인 상태로 만들고, 방송용 API와 React 오버레이로 전달한 다음 실제 화면에 표시해야 합니다.

동시에 특정 영상이나 카드 조합에서의 성공을 다른 카메라·화면 배치·전체 카드에 대한 일반 성능으로 확대하지 않아야 했습니다.

## 제품 경로

Python OCR의 상태를 Bridge와 Broadcast API로 연결하고, React 오버레이가 WebSocket으로 방송 상태를 구독하도록 구성했습니다. 사용자의 수동 보정이 자동 인식에 의해 즉시 덮어써지지 않도록 보정 우선순위도 다룹니다.

## 핵심 판단

### 모델 점수와 제품 지연을 분리했습니다

모델 추론 시간만 보지 않고 영상 입력부터 API 전달과 오버레이 표시까지의 경로를 검증하는 방향으로 구성했습니다. 정확도, 오탐, 상태 안정성과 전체 경로 지연을 서로 다른 평가 축으로 다룹니다.

### 실행 프로필의 범위를 고정했습니다

승인된 입력 범위와 모델 파일을 프로필로 구분하고 파일 해시와 로딩 실패를 검사합니다. 승인되지 않은 모델이 조용히 대체 실행되거나, 개발용 후보가 검증된 모델처럼 동작하지 않게 경계를 둡니다.

### 실패를 승격 보류의 근거로 사용했습니다

독립 입력에서의 검증과 개발 과정에서 사용한 영상의 평가를 구분합니다. 인식 범위나 오탐 조건이 충분하지 않다면 좋은 일부 수치가 있어도 범용 성능이 확보되었다고 표현하지 않습니다.

## 현재 결과

이 프로젝트는 입력 범위를 제한한 MVP를 개발·검증하는 단계입니다. 방송 제품 경로와 평가 체계를 구성했지만, 범용 52장 인식·상용 배포가 완료되었다는 주장은 하지 않습니다.

핵심 경험은 **AI 출력을 기능으로 연결하는 것과, 그 기능이 유효한 조건을 명시하는 것**을 함께 다룬 데 있습니다.
