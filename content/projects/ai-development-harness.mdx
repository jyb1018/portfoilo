## 반복되던 문제

AI와 개발 작업을 진행할 때마다 목표, 작업 범위, 승인 조건, 완료 기준을 다시 설명해야 했습니다. 반대로 모든 지침·도구·역할을 상시 주입하면 작업마다 필요한 정보가 흐려지고 관리 부담이 커질 수 있었습니다.

## 공통으로 뽑은 것

가정 확인, 작은 변경, 권한 경계, 테스트와 완료 보고처럼 여러 프로젝트에서 반복되는 규칙을 공통 핵심으로 정리했습니다. 디버깅, 검증, 리뷰 등은 작업에 따라 선택하는 스킬로 분리했습니다.

## 개별로 남긴 것

프로젝트의 업무 규칙, 런타임, 배포 승인, 데이터 접근 범위는 로컬에 남겼습니다. 공통 하네스가 도메인의 의미까지 대신 결정하거나 전역 설정과 인증을 자동 변경하지 않도록 제한했습니다.

## 구현과 사용 방식

Python 설치 도구와 프로젝트 내부 진입점을 제공해 빈 프로젝트에도 적용할 수 있도록 했습니다. 업데이트 소스를 받는 동작과 실제 지침을 적용하는 동작을 구분하고, 충돌과 변경 계획을 확인하는 경로를 마련했습니다.

## AI 활용 방식

AI는 탐색과 구현을 가속하는 데 적극 활용합니다. 대신 도구가 설치되어 있다는 사실, 현재 권한으로 사용 가능한 상태, 실제로 실행하여 검증한 상태는 구분합니다. 사용할 수 없는 기능은 명시적으로 알리고 대체 경로를 택하도록 구성했습니다.

## 결과와 평가 범위

반복되던 개발 지침을 공개 패키지로 정리하고 다른 프로젝트에서 재사용할 수 있게 했습니다. 구성·설치 검증과 제한된 행동 관찰이 존재하지만, 이것이 특정 모델의 우월성이나 생산성 개선율을 증명하는 것은 아닙니다.

핵심 성과는 많은 규칙을 추가한 것이 아니라 **공통화할 범위와 프로젝트에 남길 범위를 분리한 것**입니다.
